# nutramigen_activations

**Flip the Mobile**: the Nutramigen ELEVATE congress quiz. It's a mobile web game built with Handlebars (`index.hbs`), SCSS, JavaScript and GSAP, and hosted on Cloudflare.

---

## 1. First-time setup (once per computer)

1. Install **Node.js 20 or newer** from https://nodejs.org (choose the LTS version). To check whether you already have it:

   ```bash
   node -v
   ```

2. Go to the project folder:

   ```bash
   cd /Users/tiff/nutramigen_activations
   ```

3. Install the project's tools: Handlebars, Sass, GSAP and Cloudflare's Wrangler. They go into `node_modules/`, which git ignores.

   ```bash
   npm install
   ```

---

## 2. Commands

Run all of these from the project folder.

| What you want to do | Command | What happens |
| --- | --- | --- |
| **Work on the game** | `npm run dev` | Builds the game, serves it at **http://localhost:5173**, opens it in your browser, and rebuilds every time you save. Refresh the browser to see changes. Press **Ctrl + C** to stop. |
| **Build** | `npm run build` | Turns `index.hbs` + `questions.json` into `dist/index.html`, compiles SCSS into `dist/css/styles.css`, and copies `img/`, `js/` and GSAP into `dist/`. |
| **Package (zip)** | `npm run package` | Builds, then zips `dist/` into **`nutramigen-activations.zip`** to hand off or upload anywhere. |
| **Test like Cloudflare** | `npm run preview` | Builds and runs the site in Cloudflare's local runtime. |
| **Deploy from your computer** | `npm run deploy` | Builds and publishes to Cloudflare. Run `npx wrangler login` once first. You normally don't need this, because pushing to GitHub deploys automatically. |

**Testing the idle popup:** add `?warn=5&reset=5` to the URL, e.g. http://localhost:5173/?warn=5&reset=5. That shortens the wait before the popup and the wait before the reset to 5 seconds each.

## 3. File structure

```
index.hbs            ← ✏️ THE MAIN PAGE: every screen's layout and on-screen copy
questions.json       ← ✏️ THE 5 QUESTIONS: fed into index.hbs
img/                 ← ✏️ ALL images in one folder (no subfolders)
scss/                ← ✏️ styles
│  main.scss         ←    entry file: lists the partials below
│  _variables.scss   ←    colors, fonts, sizes, background image names, ornament size
│  _base.scss        ←    page reset, layout
│  _shared.scss      ←    headlines, "tap" prompt, Return-to-start bar
│  _attract.scss     ←    screen 1: "Tap anywhere to begin"
│  _home.scss        ←    screen 2: the mobile + ornaments
│  _question.scss    ←    screen 3: progress bar, question card, results
│  _end.scss         ←    screen 4: score + QR code
│  _modal.scss       ←    "Are you still there?" popup
js/
│  animations.js     ← ✏️ ALL GSAP animations (sway, zoom, ornament flip, card intros)
│  app.js            ←    game logic: which screen shows, scoring, reset
│  idle.js           ←    inactivity timer
│  config.js         ←    timings: popup after 45s, reset 30s later
_headers             ← Cloudflare cache settings
scripts/build.mjs    ← the build (used by the npm commands)
wrangler.jsonc       ← Cloudflare config
package.json         ← the npm commands
dist/                ← GENERATED by the build. Never edit; it's rebuilt every time.
```

## 4. Editing

### The main page: `index.hbs`

This is a normal HTML page with Handlebars tags in it. All on-screen copy (titles, buttons, the end screen, the idle popup) is typed straight into this file. Questions are pulled in from `questions.json`:

| In `index.hbs` | Means |
| --- | --- |
| `{{#each questions}} … {{/each}}` | Repeat this block once per question |
| `{{question}}`, `{{info}}`, `{{label}}` | That question's text |
| `img/{{before}}`, `img/{{after}}` | That question's ornament images |
| `{{#each answers}} {{letter}}. {{text}} {{/each}}` | The 4 answers, labelled A–D |
| `{{correctAnswer.letter}}. {{correctAnswer.text}}` | The correct answer |
| `{{total}}` | Number of questions (5) |
| `{{!-- … --}}` | A comment; it isn't output |

Keep the `class="js-…"` names and the `data-…` attributes, because the game logic uses them to find things.

### The questions: `questions.json`

```json
{
  "id": "milk",
  "label": "Milk carton ornament",
  "x": 50,
  "y": 50,
  "before": "milk-problem.png",
  "after": "ice-cream-solution.png",
  "question": "What is the most common food allergy among infants and children younger than age 3?",
  "answers": ["Cow’s milk protein allergy", "Answer B", "Answer C", "Answer D"],
  "correct": "A",
  "info": "Only Nutramigen has been clinically shown to help babies…"
}
```

| Field | Meaning |
| --- | --- |
| `id` | Unique short name |
| `label` | What screen readers announce for the ornament |
| `x`, `y` | Where the ornament hangs on the mobile: % from the left, % from the top |
| `before` | "Problem" ornament (`-problem.png`): what the mobile shows before the question is answered. A file name from `img/`. |
| `after` | "Solution" ornament (`-solution.png`): shown on the question screen, and on the mobile after a **correct** answer |
| `answers` | Exactly 4 |
| `correct` | `"A"`, `"B"`, `"C"` or `"D"` |
| `info` | The statement shown under the result |
| `incorrectImage` | "Incorrect" ornament (`-incorrect.png`): shown after a **wrong** answer, on the question screen and on the mobile. If left out, the problem image is used. |

The build checks this file. If something's wrong (a missing image, 3 answers instead of 4, a bad `correct` letter), the terminal names the exact question and problem. JSON is strict: keep the double quotes, put commas between items, and don't add a comma after the last item.

### Images: `img/`

- Put every image directly in `img/`, with no subfolders.
- In `questions.json`, use just the file name: `"before": "milk-problem.png"`.
- In `index.hbs`, use `img/file-name.png`.
- In SCSS, use `url("../img/file-name.png")`. The background images are set by name in `_variables.scss` (`$bg-attract`, `$bg-mobile`, `$bg-end`).
- PNG, JPG, SVG and WebP all work. Use **transparent PNGs** for ornaments.

### Animations: `js/animations.js` (GSAP)

Each moment in the game has its own function, so you can change the motion without touching the game logic:

| Function | When it runs |
| --- | --- |
| `swayOrnaments` | Always: the gentle swing of every ornament |
| `zoomIntoOrnament` | An ornament is tapped: the mobile zooms into it |
| `flipOrnament` | Back on the mobile after answering: that ornament flips from `before` to `after` |
| `introQuestion` | Question opens: the ornament pops in and the card slides up |
| `bobbleQuestionImage` | Correct answer: the big ornament stays as is and bobbles left/right |
| `flipQuestionImage` | Wrong answer: the big ornament flips to its `-incorrect` art |
| `revealResult`, `setProgress`, `introEnd` | Result card, progress bar, end screen |

GSAP is installed from npm and copied into `dist/js/vendor/` by the build, so it works offline at the booth. GSAP docs: https://gsap.com/docs/v3/

### Styles: `scss/`

- Change colors, fonts, sizes and background images in **`_variables.scss`**.
- Each screen has its own partial. `npm run dev` recompiles when you save.
- To add a partial, create `scss/_name.scss`, start it with `@use "variables" as *;`, and add `@use "name";` to `main.scss`.

## 5. Saving and publishing

Cloudflare rebuilds and deploys automatically every time `main` is pushed to GitHub.

```bash
git add -A
```

```bash
git commit -m "Describe what you changed"
```

```bash
git push origin main
```

If `git push` asks for a password, use a **GitHub personal access token**, not your GitHub password. Create one at GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens, with access to this repo and **Contents: Read and write**. Or push with **GitHub Desktop**.

Check the build at dash.cloudflare.com → Workers & Pages → **nutramigen-activations** → Deployments.

## 6. How the game works

Layout and flow follow the **Wireframe** page in the Figma file *Nutramigen_Activations*.

1. **Attract**: tap anywhere to begin.
2. **Flip the Mobile**: tap an ornament and the mobile zooms into it.
3. **Question**: progress bar (`#/5` on the left, `XX% Complete` on the right), the ornament, and the question with answers A–D.
4. **After answering**: the ornament stays on its solution image if correct, or flips to its incorrect image if wrong. Back on the mobile, that ornament flips the same way. The card shows *Your answer* and *Correct answer*, then the statement, then **Select another ornament →** (or **See my score →** on the last question). Back on the mobile, that ornament flips to its new art.
5. **End**: "Congratulations! You have scored a X/5." with the QR code.
6. **Idle**: after 45s with no taps, an "Are you still there?" popup appears. If nobody answers within 30s, the game resets to the start.

## 7. Cloudflare (already set up)

The Cloudflare Worker `nutramigen-activations` is connected to this GitHub repo. On every push to `main`, Cloudflare runs `npm install`, then `npx wrangler deploy`. That command runs `npm run build` first (set in `wrangler.jsonc`) and then publishes `dist/`. If a build fails, open the failed deployment → **View build log**.
